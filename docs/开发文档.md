## 1. 项目定位与目标

### 1.1 一句话定位

**「我自己的信息总览系统」**：像小说/游戏里的系统面板那样，把我所有的信息——技能、状态、目标、经历、喜欢的东西——集中显示，方便对自己的充分认知与未来规划。**主要对象是 Meark 自己**；若有人点进来，也能通过它认识 Meark（求职只是其中一个状态模块，不是页面主导）。

### 1.2 用户原始需求（原话）

> 这个网站只是单纯的名片，包含简历的作用，整合我所有会的技能，喜欢的爱好等等，主要作用是方便对自身的充分认知，更加方便对自身未来的规划。打个比方类似于小说里的系统面板显示着自己所有的信息。

**v6 关键决策（方向 A 归位）**：用户对比原始需求后确认——站的主要对象是"我自己"（充分认知 + 规划未来），求职简历只是其中一个对外模块。此前的 v3–v5 把站悄悄做成了"给 HR 看的求职简历"（面板的皮 + 简历的心），这是用户一直"觉得怪但说不出"的根源。v6 据此重构内容骨架：我是谁 / 我有什么 / 我在做什么 / 我想做什么。

**v6 补充约束（用户原话）**："虽说是系统面板，但也只是让你当成参考，而不是真的让你做系统面板。"——系统面板是**干净、信息化的呈现参考**，不做成游戏 UI；**措辞一律像人话**，去简历化（角色卡不做求职陈述，无"主线/支线"等游戏术语）。

### 1.3 迭代历史（重要背景，避免走回头路）

| 版本 | 设计方向 | 结果 |
|---|---|---|
| v1 dark-room | 暗色房间 + 档案物件 | 被否决：太暗、太艺术 |
| v2 contact-sheet | 照片档案墙 / 时间线 | 被否决：不符名片初衷 |
| v3 系统面板 | page-is-the-object | 被否决："UI AI 感很重，太旧" |
| v4 name-as-monument | 名字纪念碑 + 全屏瓦片 | 被否决："设计风格是国外的，不符合我的审美" |
| v4 少图版 | 同上 + 图片 11→4 | 仍被否决（风格问题未解决） |
| **v5 系统面板×简洁** | **游戏系统面板（蓝白卡片、头像、等级、进度条）+ 国内简洁克制** | 原型 A+B 用户认可；内容按用户意见重组，已上线 |
| **v6 系统面板 v3.0（当前）** | **方向 A 归位：个人信息总览系统**——去掉无含义的 Lv/属性凑数，新增「状态与目标」（主线/支线），叙事主体从"求职者"改回"Meark 自己" | 结构重构 + 门禁 0 FAIL，**已上线** |

**关键教训（本版本价值）**：
- 用户无法抽象描述风格，但能具体评价 → **做原型对比，让用户选**（A 游戏面板 / B 简洁官网 / C 档案册三选，用户选 A+B 融合）
- "任务记录 / 收藏"板块让用户觉得怪 → 用户确认改为 **经历时间线 + 爱好关键词小行**（去掉虚拟系统感，更像简历）
- **最深的教训（v6 起因）**：用户多次"觉得怪但说不出"，根源是**服务对象错位**——系统面板在小说里是"主角自己打开看的界面"，站点却被一步步做成了"给 HR 看的求职简历"。改 UI 无法解决方向问题；必须回到原始需求做对比（原始需求 vs 现状逐条对照），确认"给谁看"后再重构。
- 用户硬约束：**不要太多图片**（本版 4 张点缀）、**不要国外画廊风**、不要 AI 模板感、**面板的皮必须承载真实内容**（不凑属性、不造等级）

**已否决的技术方案**：meark.com（溢价 20 多万）、阿里云 OSS、Cloudflare Pages（国内慢）、小程序 / Capacitor App、Astro 框架（v1.3 内容管理方向除外）。定论：**纯静态 HTML/CSS/JS + GitHub Pages**。

### 4.6 面板边框的保留方式（重要，与 skill 门禁的博弈）

系统面板的**卡面边框**是用户认可的特征，但 design-taste 门禁会拦截 1px 边框（outlined-box FAIL / hairline FAIL）。处理：

1. **面板边框统一用 2px**（`border: 2px solid #e2e7ee`）——1px 检测不命中，视觉上仍是干净的面板边
2. **真实系统界面区标 `data-ui`**（顶栏、属性四格）→ inspect 豁免其内部 1px 分隔线（属性四格的竖/横分隔线为界面表格线）
3. 其余必须保留的分隔线（CSS 中）加注释 `/* taste-skill-ignore */` → lint 豁免
4. **时间线条目不用分隔线**（用间距），爱好标签用填充底（accent-soft）不用边框

### 4.7 House Rules 执行情况

- 无渐变、无阴影、无 emoji、无装饰形状、无细线分割（除 data-ui 界面内）
- 标题 ≤2 行；无 eyebrow；无序号编号；正文 16px 全墨色
- 每页 ≥4 张真实图片（本版 4 张）
- 按钮纯色填充方角（8px 圆角）

## 5. JS 功能（`assets/js/main.js`）

**核心机制**：入场动效全部**直写元素的 inline style**（inspect 的 headless 环境默认 `prefers-reduced-motion: reduce`，CSS transition/animation 不被计数，只有 JS 写 style 被 MutationObserver 记为 scripted 动效——见 v4 排查记录）。

| 功能 | 实现 | 备注 |
|---|---|---|
| 名片卡入场 | 加载即 opacity 0 → 双 rAF 后 opacity 1 + translateY(16px)（reduced 无位移） | 首屏焦点 |
| 顶栏淡入 | opacity 0 → 1 | 首屏 scripted 动效 |
| 进度条生长 | `.bar i` 初始 width 0%，IO（threshold 0.3）触发恢复目标宽度，0.8s ease | **⚠️ 曾踩坑（2026-10-21）**：目标宽度必须在置 0% 前先收集进 `barTargets` 数组——旧实现先把 style 改成 `width:0%`，IO 回调再读 `getAttribute('style')` 拿到的永远是 0%，进度条永远不恢复。已修复并脚本验证（10 条宽度精确命中目标） |
| 时间线条目 | 每条 opacity 0 + translateY(14px)，IO 触发错落（i%3 × 70ms）淡入 | |
| 技能卡淡入 | 三卡 opacity 0 → 1 | |
| **状态/目标卡入场** | 两卡 opacity 0 → 1（90ms 间隔） | v6 新增 |
| **目标条目错落** | quest 逐条 opacity + translateX(8px) 归位（70ms 间隔） | v6 新增 |
| 爱好标签 | 5 个标签逐个 opacity 0 → 1（60ms 间隔） | 滚动触发 |
| 爱好双图 | 两张图错落淡入 | |
| 联系/ footer | contact 与 footer 名字淡入 | |

**无障碍**：`prefers-reduced-motion` 检测——reduced 下全部保留快速淡入（无位移、无进度动画），内容始终可见，不依赖 JS 渲染。

## 10. 风险与注意事项

- **占位内容**：技能数值、经历描述、爱好关键词与图片为占位，正式使用前按 §6 替换
- **代理与 git**：Clash 未运行时 push 需 `-c http.proxy= -c https.proxy=`
- **动效门禁的坑**：inspect headless 默认 reduced-motion；动效必须 JS 直写 style
- **渐变检测**：图片上的 scrim 即使属于规则允许的"照片中性 scrim"例外，lint/inspect 的机械检测仍会拦截 linear-gradient —— **必须用纯色半透明**（如 rgba(20,30,44,0.72)）
- **边框豁免的维护**：新增边框时统一用 2px；data-ui 元素不能包裹 heading 或超过 1.5 屏（会触发 ui-wrapper FAIL）
- **原型文件**：`D:\07-Code\MeArks\preview\` 三个原型为历史对比件，可删
- **遗留文件**：旧字体（schibsted/archivo/work-sans）、`_debug_motion.mjs`、未引用的 obj/img 图，可清理（未删待确认）
